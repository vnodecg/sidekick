# Data model

Status: Draft v1 · Implements PRD §9 · Engine: SQLite via `node:sqlite` (ADR-003) · Access: Drizzle ORM (ADR-013)

## 1. Rules

- One file, `SIDEKICK_DB_PATH`. Pragmas on open: `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=3000`.
- Every domain table (all except `__drizzle_migrations`) has `user_id TEXT NOT NULL` (v1 value `"default"`) and every query filters on it. Repositories take `userId` as the first argument; there is no query without it.
- Times: `INTEGER` UTC epoch **seconds**. Local dates (`routines.last_done_on`) are `TEXT 'YYYY-MM-DD'` in `SIDEKICK_TZ`. Display conversion only in `core/timewords.ts` and `core/clock.ts`.
- Seconds resolution means timestamps tie. Every `ORDER BY <timestamp>` adds `id` in the same direction as a tie-break so "latest" is deterministic.
- Booleans are `INTEGER 0/1` with `CHECK`. Enums are `TEXT` with `CHECK`.
- Single process, single writer. Multi-statement writes use `tx(db, fn)` from `db/connection.ts` (a Drizzle transaction with `behavior: "immediate"`); no `await` inside.
- Migrations: generated by `drizzle-kit` from `src/db/schema.ts` into `src/db/migrations/<timestamp>_<name>/migration.sql`, applied at open by Drizzle's migrator and tracked in `__drizzle_migrations`. Forward-only; v1 ships `init`. Never edit an applied migration; change the schema and run `npm run db:generate`.
- Privacy: `ai_calls` holds metadata only (model, attempt, outcome, latency). Never prompt text, task text or error messages.

`wins.ref_id` is a soft reference (no FK) so deleting or archiving a source never blocks or rewrites history. `wins.text` is a copy of the source text for the same reason.

## 3. Schema

**Source of truth: [`src/db/schema.ts`](../../src/db/schema.ts)** (Drizzle `sqliteTable` definitions). The generated DDL is in `src/db/migrations/`. This document does not repeat the DDL, so there is nothing to drift. What the schema guarantees:

| Table | Constraints beyond column types |
|---|---|
| `tasks` | `UNIQUE (user_id, id)`; composite FK `(user_id, parent_id) -> tasks (user_id, id) ON DELETE CASCADE`; parent rows have `position = 0`, steps `>= 1`; `source` only on parents; `status = 'done'` iff `completed_at IS NOT NULL`; enums on `status` and `source`; partial index `tasks_user_active` on parents |
| `wins` | `kind` enum: `step, task, focus, routine, manual`; `ref_id` is a soft reference (no FK) |
| `focus` | `planned_minutes` in 1..240; `ended_at >= started_at`; partial unique index `focus_one_open (user_id) WHERE ended_at IS NULL` |
| `routines` | `time_of_day` matches `HH:MM` 24h; `last_done_on` matches `YYYY-MM-DD`; partial index on non-archived rows |
| `dopamine`, `ai_calls` | boolean columns carry `CHECK (x IN (0,1))`; `ai_calls` has no text columns |
| all | `user_id TEXT NOT NULL`; every `(user_id, ...)` list index orders `created_at DESC` |

Booleans are `integer({ mode: "boolean" })`, so callers see `true/false` and the database stores 0/1. Enum columns are typed as string-literal unions from the same constants the `CHECK`s use.

PRD delta: `ai_calls` is new (PRD §9). Added beyond PRD column lists: `archived_at`, `status`, `source`, `last_used_at`, `planned_minutes` (see §6).

## 4. Seeds

`dopamine` defaults are inserted lazily per user on first `dopamine_menu`/`what_now`/`match_energy` read (`ensureSeeded(userId)`, `is_default=1`): stretch for one minute; drink a glass of water; step outside for fresh air; put on one favourite song; do ten slow breaths; walk to another room and back; text a friend a silly emoji; doodle for two minutes. Defaults are not deleted by `gentle_reset`; `delete_my_data` removes them (re-seeded on next use).

## 5. Query catalogue (canonical)

| Name | Used by | Index | SQL sketch |
|---|---|---|---|
| activeTask | next/complete/park | `tasks_user_active` | `SELECT * FROM tasks WHERE user_id=? AND parent_id IS NULL AND status='open' ORDER BY updated_at DESC, id DESC LIMIT 1` |
| currentStep | next/complete | `tasks_user_parent_status` | `... WHERE user_id=? AND parent_id=? AND status='open' ORDER BY position LIMIT 1` |
| completeStep (tx) | complete_step | primary key | update step done and set `completed_at`; touch parent `updated_at`; insert win; if no open step, update parent done and set `completed_at` + win |
| openFocus | focus tools, what_now | `focus_one_open` | `WHERE user_id=? AND ended_at IS NULL` (unique index guarantees <= 1) |
| recentDump | sort_dump | `dump_user_created` | `WHERE user_id=? AND archived_at IS NULL ORDER BY created_at DESC, id DESC LIMIT 6` (6th row tells "and more") |
| lastParked | where_was_i | `parked_user_created` | `WHERE user_id=? ORDER BY created_at DESC, id DESC LIMIT 1` |
| winsSince | my_wins | `wins_user_created` | `WHERE user_id=? AND created_at >= ? ORDER BY created_at DESC, id DESC` |
| dueRoutine | routine_check, what_now | `routines_user` | `WHERE user_id=? AND archived_at IS NULL`, then filter in JS in local time; rule: TOOLS §5 `routine_check`; order by `time_of_day` |
| nextBreak | dopamine_menu | `dopamine_user_used` | `WHERE user_id=? ORDER BY last_used_at IS NOT NULL, last_used_at, id LIMIT 1` then stamp (never-used rows first, then least recently used) |
| deleteAll (tx) | delete_my_data | `user_id` prefix of each index | `DELETE FROM <t> WHERE user_id=?` for all 8 domain tables; `tasks` also cascades steps via the composite FK |

## 6. Interpretation notes (PRD silent)

| Topic | Decision |
|---|---|
| Task lifecycle | `open -> done`, or `open -> archived` (gentle_reset). Nothing is "overdue"; there is no due date. `completed_at` is set exactly when `status='done'` (enforced by `CHECK`). |
| `source` on parent | Lets the UI/demo show whether steps came from Bedrock; never spoken. Steps carry NULL (enforced). |
| Tenant integrity | The composite FK `(user_id, parent_id)` makes a cross-user parent/step link unrepresentable, not just unqueried. |
| Wins never deleted | Except by `delete_my_data`. `gentle_reset` keeps them. |
| Retention | None in v1. A single user's volume is tiny. |
| Backup | WAL mode means the `-wal` and `-shm` files hold committed data, so copying the main file alone can lose writes. Use `VACUUM INTO 'backup.db'`, or stop the server and copy all three files. Documented in README. |
| Multi-user later | Add `users` table and FK; today `user_id` is just a partition key. No cross-user query exists to refactor. |
